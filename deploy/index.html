SentinelRelay · Cloudflare Worker

部署向导

在浏览器中校验 Telegram 配置，并生成可直接粘贴到 Cloudflare Workers 的单文件 Worker。密钥只在当前页面内存中处理，不会上传、下载或写入浏览器存储。

1. 填写运行配置

带 * 的项目必填。Telegram Bot Token、Turnstile Secret 和 Webhook Secret 使用密码输入框；生成后请把它们视为已暴露，必要时立即轮换。

在 Telegram 中打开 @BotFather，发送 /newbot 或进入已有 Bot，复制完整的“数字:密钥”内容，不要带空格。
把 Bot 加入开启 Topics 的 Telegram 超级群；群 ID 通常以 -100 开头，可用 API 验证按钮确认类型和 Topics 状态。
填写将来部署 Worker 的公开 HTTPS 根地址，只保留 origin，例如 https://relay.example.com，不要加路径、查询参数或末尾斜杠。
在 Cloudflare Turnstile 创建站点后，从站点配置复制 Site Key；它可以公开显示，用于浏览器验证组件。
在同一个 Turnstile 站点的密钥页面复制 Secret Key；它只写入生成代码，不能公开分享或提交到 Git。
自己生成 16–256 位随机字符串，只使用字母、数字、下划线或连字符；Telegram 会把它放在 Webhook 请求头中。
填写 5–1440 的整数，单位是分钟；30 分钟适合大多数场景，时间太短可能来不及完成验证。
填写 WebRTC ICE 使用的 STUN 地址，必须以 stun: 开头；不确定时保留默认的 stun:stun.miwifi.com:3478。

2. 复制 Worker 代码

代码只保留在当前页面内存中；关闭或刷新页面后会被清空。
